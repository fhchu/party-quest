# Design calls

Design calls (UI, game design, code and system architecture) are the
owner's. What `AGENTS.md`, `.agents/rules/*.md` and the skills in
`.agents/skills/` say are calls the owner has already made: follow them
without asking, and when the rule isn't obvious, name it in your reply to
the owner.

Ask before any choice the rules don't settle (names, where things go,
what to keep or drop) or where two of them conflict, even mid-task when
one option looks obvious to you. Branch names are the exception: pick
them yourself and never ask about them.

Offer only options that follow the rules, except where two rules
conflict; never list one whose cost is breaking a written rule.

Don't ask when one option has no real cost and every other option only
adds costs or drops something it keeps. Choose the free one and name it in
your reply. List an option only if the owner could reasonably prefer it.

Give what each option gains and what it costs, and never pick one. A
cost is something concrete the owner loses or has to do: behavior that
goes away, extra work or files, a written rule it strains, a risk of
bugs. These aren't costs: the option's own description, how it differs
from another option, or a matter of taste the owner hasn't stated.
Check any fact a cost rests on (that a name is already in use, that
something breaks) before you write it. If an option has no real cost,
write "no cost" instead of inventing one.

Batch the questions and label them: number each question, and label its
options with that number and a letter (2a, 2b). A question keeps its
number until it's settled; new questions continue the count across the
conversation, never restarting. Give each option once, under its
question.
